NLP & Données de santé

Prédire un risque de crise cardiaque en le transformant en problème de texte

Sur la compétition Kaggle « Heart Attack Risk Analysis », plutôt que d'entraîner un modèle tabulaire classique, j'ai transformé chaque patient en une phrase et fait classer ces phrases par un BERT fine-tuné.

Le contexte

Le problème à résoudre

La compétition Kaggle Heart Attack Risk Analysis propose un jeu de données patients (âge, cholestérol, tension, mode de vie, antécédents...) et demande de prédire, pour chacun, s'il présente un risque de crise cardiaque : une classification binaire sur données tabulaires, l'un des cas d'usage les plus classiques du machine learning.

Le réflexe naturel sur ce genre de jeu de données est de sortir un Random Forest ou un gradient boosting (LightGBM). Je voulais plutôt tester une idée plus inhabituelle : et si on donnait ces données à un modèle de langage, en les décrivant simplement en phrases ? Ce projet est autant une expérience sur les limites de cette approche qu'une tentative de scorer sur la compétition.

L'approche

Comment j'ai construit la solution

Première étape, classique : encoder les variables catégorielles (sexe, mode de vie, pays...) en entiers via des dictionnaires de correspondance construits sur le jeu d'entraînement, pour pouvoir les réutiliser à l'identique sur le jeu de test.

Deuxième étape, moins classique : au lieu de passer ces colonnes numériques directement à un modèle tabulaire, je reconstruis une phrase pour chaque patient, du type "Age: 67, Cholesterol: 208, Sex: 1, ...", en concaténant chaque nom de colonne et sa valeur. Le problème de classification tabulaire devient alors un problème de classification de texte.

Ces phrases sont ensuite tokenisées et données à un BertForSequenceClassification (bert-base-uncased) fine-tuné avec deux étiquettes, via le Trainer de la bibliothèque Hugging Face transformers. Le modèle fine-tuné est ensuite rechargé pour l'inférence sur le jeu de test, en reproduisant exactement le même pipeline de textification que pour l'entraînement afin d'éviter tout écart entre les deux.

Dernier détail qui a son importance : les probabilités renvoyées par le modèle sur le jeu de test étaient très resserrées autour d'une même valeur plutôt que bien réparties entre 0 et 1. Un seuil de décision fixé au hasard à 0,5 aurait donc été arbitraire. J'ai inspecté la distribution réelle des probabilités prédites pour choisir un seuil de coupure plus cohérent avec le déséquilibre des classes du jeu de données, plutôt que d'utiliser la valeur par défaut.

Le pari du projet n'était pas de battre un LightGBM ou un XGBoost sur ce jeu de données (un modèle de gradient boosting reste un choix bien plus naturel et efficace pour des données tabulaires), mais de voir si un modèle de langage pré-entraîné sur du texte généraliste arrive malgré tout à extraire un signal utile une fois les données transformées en phrases.

Bien qu'arrivé 4ᵉ à la compétition soit un bon score, l'accuracy n'est pas très élévé (le premier étant à 0.64061). Néanmoins, cette approche semble être au moins aussi performante qu'un LightGBM ou XGBoost classique.

Ce que j'ai retenu

Le vrai apprentissage

Transformer des données tabulaires en texte pour les faire lire par un modèle de langage est un détournement amusant, mais ça a un coût : on perd la structure explicite des colonnes que des modèles comme LightGBM exploitent nativement (splits sur une variable précise, interactions entre features), et on la remplace par l'espoir que le modèle la retrouve lui-même dans une phrase. C'est aussi beaucoup plus lourd à entraîner et à faire tourner qu'un modèle tabulaire classique, pour un gain qui reste à démontrer sur ce type de données.

Le détail du seuil de décision m'a aussi rappelé qu'un modèle de classification binaire ne rend jamais vraiment un score entre 0 et 1 bien réparti par magie : il faut regarder la distribution réelle des prédictions avant de choisir où couper, plutôt que de garder 0,5 par réflexe.
